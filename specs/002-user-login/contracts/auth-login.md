# Authentication Login Contract

The endpoint URL is configured through `NEXT_PUBLIC_LOGIN_API_URL` until the backend
provides a fixed URL. The request and response rules below are the agreed contract.

## Request

```http
POST ${NEXT_PUBLIC_LOGIN_API_URL}
Content-Type: application/json
```

```json
{
  "username": "user@example.com",
  "password": "user-password",
  "machineCode": "fingerprint-visitor-id"
}
```

`machineCode` MUST be generated by `@fingerprintjs/fingerprintjs@5.2.0` using its
`visitorId` before the login request is sent. The password is transmitted only over the
configured secure transport and is never persisted.

## Success response

```json
{
  "status": 1,
  "accessToken": "<jwt-access-token>",
  "refreshToken": "<refresh-token>",
  "user": {
    "id": "user-id",
    "username": "username",
    "email": "user@example.com",
    "displayName": "Example User"
  }
}
```

When `status` is `1`, the frontend MUST persist the approved response fields in one
namespaced localStorage record and redirect to the fixed `/dashboard` route.

## Two-factor response

```json
{
  "status": -131
}
```

When `status` is `-131`, the frontend MUST display exactly:
`Tính năng xác thực 2 yếu tố đang phát triển`.
The frontend MUST NOT start a partial 2FA flow in this feature.

## Error responses

Invalid credentials, network failures, server failures, and malformed success payloads
MUST be normalized into a safe error shape. Failed responses MUST NOT create or overwrite
an authenticated localStorage session.
